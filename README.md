# ARVO & MAJANG — CONNECT R0.2

2026-11-25 · Mashcore × Weplace

## 1. 이번 버전의 목적
아르보호텔과 마장동을 하나의 공동 작업 공간에서 전환하되 광고·운영·매출을 혼합하지 않는다. 플랫폼 로고형 탐색과 SIX ROOMS를 함께 사용한다. 직원은 체크·현장 반응, 전략 담당자는 광고 계획·성과, 대표는 의견·승인 기록에 집중한다. 기존 설마중 운영 원본과 R0.1은 변경하지 않았다.

## 2. 파일과 현재 상태
- `Index.html`: 단독 브라우저 DEMO 및 Apps Script HTML Service용 파일. DEMO는 가상의 예시 데이터이며 기기 로컬 저장을 시도한다. 역할 전환은 체험 기능이고 인증이 아니다. 실제 운영정보를 입력하지 않는다.
- `Code.gs`: 신규 내부 Apps Script용 파일럿 백엔드. Google 계정 허용 목록·업장·역할 검증, 원장 조회, 이벤트 추가, 상태 변경과 입력 검증을 구현했다. 실제 Apps Script 배포/로그인/시트 저장 테스트 전이다.
- `appsscript.json`: V8, 한국 시간, Google Sheets 및 사용자 이메일 scope, 로그인 사용자 실행 설정.
- `desktop.png`, `mobile.png`, `guest.png`: 실제 브라우저 렌더링 검수 이미지.
- `QA.md`: 수행한 테스트와 미검증 범위.

## 3. 먼저 DEMO 확인
`Index.html`을 Chrome에서 연다. 마장동/아르보호텔 전환 → 당근 로고 → 발행물 및 비용 기록 → 함께 판단에서 의견 및 승인 → 손님 시안을 체험한다. 모든 수치와 승인 기록은 가상이다. 실제 운영에 영향을 주지 않는다.

## 4. 신규 Google Sheets 연결 — 승인된 소수의 신뢰된 관리자 파일럿만
**기존 설마중 시트/코드에 덮어쓰지 말 것.** 새 시트와 독립 Apps Script 프로젝트를 사용한다.

1. 새 빈 Google Sheets 파일을 생성하고 URL의 `/d/`와 `/edit` 사이 스프레드시트 ID를 복사한다. 내부 파일은 인터넷 공개하지 않는다.
2. `script.google.com`에서 신규 독립 프로젝트를 생성한다. `Code.gs`에 제공된 백엔드 내용을 붙인다. HTML 파일 `Index`를 추가하여 제공된 `Index.html` 내용을 붙인다. 프로젝트 설정에서 매니페스트 표시를 켜고 필요하면 제공된 `appsscript.json`을 적용한다.
3. 프로젝트 설정 → 스크립트 속성에서 `CONNECT_SHEET_ID`와 `CONNECT_MEMBERS_JSON`을 등록한다. 아래 값은 예시이며 실제 승인 계정으로 바꾼다. 두 업장 데이터와 재무 원장을 모두 열어볼 권한이 있는 신뢰된 파일럿 운영자만 우선 포함한다.

```
CONNECT_SHEET_ID = 새 시트의 ID
CONNECT_MEMBERS_JSON = {"owner@example.invalid":{"role":"owner","units":["hotel","restaurant"]},"strategist@example.invalid":{"role":"strategist","units":["hotel","restaurant"]}}
```

4. 시트에 `CONNECT_EVENTS` 탭을 만들고 A1에 다음 헤더를 탭으로 구분하여 붙여넣는다. C열과 G열을 일반 텍스트로 설정한다. 또는 설정 후 소유자 계정으로 스크립트 편집기에서 `initializeWorkspace_()`를 실행한다(기존 동일 탭을 덮어쓰지 않음).

```tsv
event_id	unit	business_date	type	payload_json	actor_email	recorded_at
```

5. 배포 → 새 배포 → 웹 앱. 실행 사용자 **웹 앱에 액세스하는 사용자**, 접근 범위 **로그인한 사용자**로 선택한다. `모든 사용자(익명 포함)` 또는 `나로 실행`으로 배포하지 않는다. 계정별 설정명과 제공 범위는 Workspace 정책에 따라 다를 수 있다. 기존 운영 배포를 수정하지 않는다.
6. 승인된 계정에게만 원장 편집 권한을 부여한다. 두 계정 각각에서 OAuth 승인, 접속, 입력, 새로고침, 상대 계정 화면 반영을 확인한다. 미승인 계정, 잘못된 업장 권한과 역할, 중복 요청, 동시 상태 변경도 테스트한다. 정상 확인 전에는 실제 데이터를 등록하지 않는다.

**중요한 한계**: 파일럿은 접근 사용자의 Google 권한으로 시트를 읽고 쓴다. 원장에 직접 편집 권한을 준 계정은 웹앱의 역할별 표시/변경 제한을 우회해 시트 원본을 볼 수 있다. 진짜 재무·업장별 보안 경계가 필요하면 직접 시트 공유를 하지 않는 인증 백엔드 또는 별도 원장을 도입한다. 독립 스크립트는 운영자 외에 편집 권한을 공유하지 않는다. 공개 QR 고객 페이지는 별도 배포/별도 스크립트/쓰기 전용 원장, 스팸 방지, 개인정보 안내로 검수 후 구축한다. 현재 공개 접수용으로 배포하지 않는다. LIVE에서는 내부 손님 시안이 설문을 저장하지 않는다.

## 5. 데이터 구조와 집계 기준
이벤트 단일 원장에는 이벤트 ID/업장/영업일/유형/JSON/실행 계정/기록 시각을 저장한다. 기존 행 수정·삭제 대신 새 이벤트를 추가한다. 동일 광고 채널+캠페인 코드+영업일 성과는 최신 스냅샷만 집계한다. 실적 전체와 점심·저녁을 중복 합산하지 않는다. 운영 점검은 고유 키를 사용하며 완료를 별도 기록한다. 승인 요청→승인/보류는 서버 역할과 현재 상태를 확인한다. 승인은 당근 실제 집행이 아니다. 동일 요청 ID 재시도는 기존 기록 반환; 실패 뒤 새 ID로 재입력하면 중복될 수 있어 원장 확인이 필요하다. 매출은 실제 POS/PMS 기준, 서비스비는 실제 원가, 미측정은 빈 상태로 둔다. 매출·비용·VAT의 기준은 실제 운영자와 맞춘다. 리뷰 작성은 링크 이동과 분리, 고객 응답은 자발적이고 리뷰 작성 조건과 독립적이다. 원장 10,000 이벤트 초과 시 명시적으로 조회 중단; 운영 규모가 늘면 날짜별 조회와 페이지네이션 필요. 15초 갱신은 화면이 열리고 입력 중이 아닐 때만 내부 원장 조회; 당근 API를 15초마다 호출하지 않는다.

## 6. 당근 OpenAPI 연결 준비
공식 공지: https://business.daangn.com/notice/detail/420 (2026-10-16)
당근비즈니스 전문가모드 → 고객센터 → 온라인 문의 → 광고 도구 및 전환 → OpenAPI 키 발급. 광고주 ID와 사용 유형 단위로 발급된다. 재발급 시 기존 키는 폐기된다. 대표/광고 계정 권한자 승인과 계정 매핑을 먼저 확인한다.

공식 세부 문서(요청 URL, 인증 헤더, 메서드, 필드, 시간별 집계 가능 여부)를 확인하고 먼저 읽기 전용 조회 어댑터를 별도 비공개 서버/소유자 전용 Apps Script에 구현한다. 키는 브라우저 HTML·공유 시트·채팅·Git에 두지 않는다. 소유자 전용 스크립트 속성 또는 서버 비밀 저장소에 보관한다. 공유 편집 프로젝트에는 키를 넣지 않는다. 첫 테스트는 계정 조회 및 날짜별 성과 1회 읽기, 당근 관리자와 합계 대조, 오류 및 마지막 성공 시각 기록. 실패 시 재시도 간격 제한과 429 backoff를 적용한다. 조회 주기는 제공 데이터 갱신 지연에 맞춘다. 기본 권장 초기 1일 1회 또는 수동 실행. 자동 예산 변경·광고 등록·이벤트 전송은 이 파일럿에 미구현. 공식 대행사 전용 권한이 필요한 기능은 사용하지 않는다. 오프라인 설문을 실제 구매 전환 이벤트로 임의 전송하지 않는다.
