# MASHCORE LOCAL FLOW R0.5 · 마장동 사천본점 현장 실증

대표와 Mashcore가 영업일별로 광고 계획을 세우고, 어떤 계획을 실제로 집행했는지 기록한 뒤 매장 마감과 비교해 다음 행동을 정하는 F&B 운영 일지다. 로컬에서는 가상 사업장으로 바로 시작한다. 두 기기에서 같은 실증 기록을 보려면 별도 Google Sheets 원장과 인증된 Apps Script 연결이 필요하다.

## 바로 실행

ZIP을 풀어 `r05-field` 폴더에서 실행한다. 로컬 앱과 빌드에는 Node.js만 필요하다. 검수 환경은 Node.js 24.15.0이었다.

```powershell
node dev.mjs
```

[로컬 운영 일지](http://127.0.0.1:4305/)를 열면 상단에 **데모 · 가상 원장**이 표시된다. 프로젝트 루트에서는 `node .\r05-field\dev.mjs`를 사용한다. 서버는 이 컴퓨터의 루프백 주소에서 실행된다. 포트를 바꾸려면 `node dev.mjs 4315`처럼 번호를 지정한다.

[설치용 HTML 미리보기](http://127.0.0.1:4305/built/)에서는 Apps Script에 넣을 단일 HTML을 같은 브라우저에서 열 수 있다. 두 로컬 주소는 같은 데모 저장소를 사용한다. 대표와 Mashcore 역할은 데모 화면 상단에서 전환할 수 있다. 새 브라우저 프로필의 첫 실행 때만 오늘과 7일 전의 예시 기록을 만든다. 실제 매장 수치는 입력하지 않고, 거래·고객 단위 정보는 수집하지 않는다.

## 하루 사용 순서

| 순서 | 화면에서 할 일 | 남는 기록 |
| --- | --- | --- |
| 1. 오늘 | 영업일을 고른다. 타임테이블의 세이지색 계획과 주황색 실제 집행 시간을 확인한다. | 선택한 날짜의 방문 팀·매출·기록 광고비·관리 시간과 업무 진행 상태 |
| 2. 광고 | 채널, 소재 제목, 가설, 시간, 예산을 저장한다. 집행 후에는 당시 계획 버전을 골라 실제 시작·종료를 기록한다. | 계획 v1, v2 등이 각각 남는다. 집행 기록에는 선택한 계획 ID와 버전이 고정된다. |
| 3. 광고 실적 | 집행 건, 원천 채널, 집계 시작·종료를 고른 뒤 광고 관리 화면에서 확인한 광고비·노출·클릭을 적는다. | 수기 실적과 집계 기간. 수치를 보완하면 기존 기록을 보관하고 새 행을 추가한다. |
| 4. 마감 | 점심·저녁 방문 팀과 매출, 광고 관리에 쓴 분, 기여율, 추가 실험 비용을 입력한다. | 부분 마감부터 저장할 수 있다. 빈칸은 미측정, `0`은 관측한 0이다. |
| 5. 판단 | 앞선 비교 영업일을 선택해 영업시간·행사 조건을 확인한다. 엔진 제안을 읽고 자신의 판단과 근거를 남긴다. 두 운영자 모두 의견을 남길 수 있다. | 당시 근거, 엔진 버전·제안, 선택·사유·작성자. 대표가 해당 판단에 승인 또는 보류와 근거를 덧붙인다. |
| 6. 조회 | 영업일을 기준으로 일간·주간·월간을 선택한다. 날짜 버튼을 누르면 해당 날의 운영 화면으로 돌아간다. | 기록된 날짜 수, 지표별 측정일 수·합계, 선택한 날짜의 수정·승인 이력 |

탭을 오가도 같은 영업일·역할에서 입력 중인 판단과 선택값이 유지된다. 양식 초안은 열린 페이지의 메모리에 있다. 저장 확인이 끊긴 요청은 별도로 해당 탭의 세션 저장소에 보관해 새로고침 후에도 같은 ID로 확인할 수 있다. **충돌 입력을 버리고 최신본 열기**는 해당 양식의 초안을 비운다. 필요한 문구를 보관한 뒤 최신 값을 기준으로 다시 입력한다.

## 집계와 판단 기준

- 모든 영업일과 화면 시각은 한국시간이다. 계획 시간, 실제 광고 시간, 성과 집계 기간을 따로 입력한다. 일반 입력 화면의 광고 시작·종료는 같은 영업일 안의 시각이다. 날짜를 넘는 광고 실적 집계 기간은 입력할 수 있다. 종료 경계는 미포함이다.
- 일간 광고비에는 해당 날의 모든 집행에 대해 원천 채널이 일치하고, 영업일 00:00부터 다음 날 00:00까지의 광고비가 측정된 경우만 합산한다. 동일 채널의 하루치가 여러 집행에 중복될 수 있으면 합산을 유보한다. 일부 시간의 보고서도 원장에는 남는다.
- 방문 팀과 매출은 각각 점심과 저녁 두 값이 있어야 하루 합계가 된다. 관리 시간은 영업일 단위다. 주간은 월요일부터 일요일, 월간은 해당 달 전체다. 기간별 지표는 최신 마감·최신 집행별 실적 기준이며 측정된 날만 합산한다. **측정 0일**과 **측정 1일 · 0원**을 구분한다.
- R0.4의 클릭당 비용, 퍼센트 클릭률, 방문 차이, 가정 기여액, 손익분기 추가 팀 산식을 계승했다. 팀당 기여액은 당일 매출 ÷ 방문 팀 × 기여율이다. 가정 기여액은 방문 팀 차이 × 팀당 기여액 − 광고비 − 추가 비용이다. 손익분기 팀 수는 (광고비 + 추가 비용) ÷ 팀당 기여액을 올림한다. 방문 차이가 광고에서 비롯됐다는 가정이 들어간다.
- 한 건의 집행과 그 계획, 일치하는 채널의 하루치 실적, 양일 마감, 비교 가능한 영업 조건이 갖춰져야 유지·수정을 검토한다. 미측정, 0 노출, 계산할 수 없는 팀당 기여액, 한 날의 다중 집행 등은 사유를 표시하고 **판단 유보**만 저장한다. 0클릭이면 클릭당 비용을 계산하지 않는다.
- 판단 저장 시 서버 엔진이 원장에서 근거를 다시 구성한다. 당시 계획·집행·광고 실적·양일 마감의 ID, 버전, 입력값과 시각, 계산 지표, 제안 및 사유를 함께 저장한다. 이후 계획·마감을 수정해도 판단 이력은 저장한 사본을 읽는다.
- 3개월 실증에서는 두 운영자가 같은 범위의 업무를 기록해야 관리 시간의 주간 추이를 비교할 수 있다. 첫 주의 관리 시간과 기록한 영업일 수를 기준으로 삼고, 주·월별 측정일 수와 함께 읽는다.

## 별도 Google Sheets 원장 설치

이번 인계에서는 설치 파일을 생성하고 모의 Google 환경에서 실행했다. 실제 Sheet 생성, Google 사용자 승인, 웹 앱 배포는 수행하지 않았다. 아래 단계는 실증 담당자가 별도 테스트 원장으로 연결을 확인할 때 사용한다.

1. 대표 관리 계정으로 **새 빈 스프레드시트**와 **새 Apps Script 프로젝트**를 만든다. 스프레드시트 주소의 `/d/`와 다음 `/` 사이 값이 시트 ID다. 기존 영업·예약·ARVO 스프레드시트와 분리한다.
2. `apps-script/`의 네 파일을 설치한다. 스크립트 파일 `Code`와 `Engine`에는 각각 `Code.gs`와 `Engine.gs`를 붙여 넣는다. HTML 파일 `Index`에는 대문자 `Index.html`을 넣는다. 프로젝트 설정에서 매니페스트 파일 표시를 켜고 `appsscript.json`을 반영한다. 시간대는 `Asia/Seoul`이고 권한 범위는 Sheets와 로그인 사용자 이메일이다.
3. **프로젝트 설정 → 스크립트 속성**에 아래 값을 설정한다. 운영 계정 이메일은 서버 설정에만 둔다. 같은 사람에게 두 ID를 부여하거나 다른 계정에 같은 ID를 주지 않는다. 예시 도메인은 가상값이다.

| 속성 | 입력할 값 |
| --- | --- |
| `R05_SHEET_ID` | 새 빈 스프레드시트의 ID |
| `R05_MEMBERS_JSON` | 아래 구조의 JSON 한 줄. 이메일 키는 소문자, ID는 사람마다 다른 내부 별칭, 사업장은 `majang-sacheon` |
| `R05_MODE` | 초기화 중에는 `demo`. 속성을 생략해도 기본은 데모 |
| `R05_BOUND_SHEET_ID` | 초기화 함수가 기록한다. 설치자가 채우는 항목은 `R05_SHEET_ID`다. |

```json
{"owner@example.invalid":{"id":"pilot-owner","role":"owner","businessId":"majang-sacheon"},"ops@example.invalid":{"id":"pilot-ops","role":"mashcore","businessId":"majang-sacheon"}}
```

4. 등록된 `owner` 계정으로 Apps Script 편집기에서 `initializePilot_`를 한 번 실행하고 해당 프로젝트의 Google 권한 요청을 검토한다. 이 함수가 빈 원장에 `R05_FIELD_EVENTS` 탭과 헤더를 만들고 결합된 시트 ID를 기록한다. 재실행하면 기존 헤더를 확인한다. 다른 데이터가 있는 파일, 이미 결합된 시트 ID의 변경, 비대표 초기화 요청은 거절한다.
5. 별도 테스트 프로젝트에서 원장 초기화와 사용자 등록을 마친 뒤 `R05_MODE`를 `pilot`으로 바꾼다. 로컬 서버는 계속 데모로 작동한다. 실증 경로는 Apps Script의 `doGet`을 통해 열린 페이지에서 `google.script.run`으로 작동한다. 현장 접근을 열기 전에 조직의 테스트 환경에서 대표·Mashcore 각 계정과 미등록 계정으로 아래 수용 조건을 확인한다.
6. 웹 앱의 실행 주체와 접근 대상을 조직의 Google Workspace 설정에 맞춰 결정한다. 로그인 계정 이메일을 확인할 수 있어야 하며, 대표 소유 원장에 쓰기 권한도 있어야 한다. 개발자로 실행할 때에는 조직·승인 조건에 따라 활성 사용자의 이메일이 비어 있을 수 있다. 이 경우 앱이 접근을 거절한다. 접속자로 실행할 때에는 해당 계정의 시트 권한도 필요하다. 원장을 직접 편집할 수 있는 계정은 앱의 역할 검사를 우회하므로 원장·스크립트의 편집 권한도 따로 제한한다. 편집기 테스트 URL의 접근 범위와 웹 앱 접속 범위는 다르다. [Google 웹 앱 실행 방식](https://developers.google.com/apps-script/guides/web) · [활성 사용자 이메일 동작](https://developers.google.com/apps-script/reference/base/session)

**현장 연결 수용 조건**은 두 계정에서 **실증 · Sheets**와 자기 역할이 보이고, 한쪽이 저장한 테스트 기록이 상대방의 동기화 후 같은 ID로 조회되며, 미등록 계정과 Mashcore의 직접 승인 요청이 거절되는 것이다. 시트에 `mode=pilot`과 내부 작성자 ID가 남는지 확인한다. 헤더와 데이터 행은 앱이 관리한다.

### 저장과 복구

| 동작 | 실제 구현 |
| --- | --- |
| 권한 | 서버가 활성 Google 사용자와 허용 목록에서 사업장·사용자·역할을 결정한다. 대표와 Mashcore는 입력과 공동 판단을 할 수 있고, 대표만 원장 초기화·승인·보류를 할 수 있다. 데모 역할 선택은 실증 권한에 영향을 주지 않는다. |
| 원장 | 이벤트 한 건은 한 행이다. `event_id, business_id, mode, business_day, day_version, event_type, actor_id, role, updated_at, data_json, evidence_json`을 기록한다. ID는 요청을 처음 만들 때 발급하고, 수정 시각은 서버가 UTC로 부여한다. 새 수정은 새 ID와 영업일 버전을 갖는다. |
| 관계 | `plan → run → report`로 당시 계획을 고정한다. `close`는 영업일별 마감이다. `opinion`은 운영 의견, `decision`은 선택·사유와 당시 자료, `approval`은 특정 판단을 대상으로 한 대표의 최종 검토다. |
| 동시 저장 | 서버가 스크립트 잠금을 잡고 현재 영업일 버전을 다시 읽는다. 같은 버전으로 들어온 서로 다른 요청은 먼저 반영된 쪽만 저장된다. 비교일 마감이 교체된 경우도 공동 판단을 다시 검토해야 한다. [Google Lock Service](https://developers.google.com/apps-script/reference/lock/lock-service) |
| 응답과 재시도 | 쓰기·`flush`·행 재조회 후 확인 ID와 원장을 반환한다. 클라이언트는 사업장·사용자·입력 내용·ID를 대조해 **저장 완료**를 표시한다. 응답 지연이나 쓰기 오류 시 **같은 저장 요청 재시도**를 사용한다. 이미 반영된 요청의 확인은 기존 행을 사용한다. 성공한 동기화 시각과 오류는 화면에 표시된다. [Apps Script HTML 통신](https://developers.google.com/apps-script/guides/html/communication) |
| 저장소 경계 | 로컬 데모는 Web Locks와 브라우저 `localStorage`에 가상 사업장만 저장한다. 실증 원장은 별도 사업장·시트에 둔다. 연결이 끊기거나 계정이 거절되면 실증 저장이 성공으로 표시되지 않는다. 실증의 미확인 재시도 요청만 해당 브라우저 탭의 `sessionStorage`에 일시 보관한다. |

### 소스와 빌드

```text
r05-field/
  index.html                 로컬 진입점과 다섯 운영 화면
  dev.mjs                    외부 패키지 없는 루프백 정적 서버
  build.mjs                  ES 모듈로부터 설치용 HTML·서버 엔진 생성
  README.md                  실증 인계와 설치 절차
  src/
    config.mjs               사업장·역할·채널·한국시간 날짜 및 기간 설정
    flow.mjs                 일·주·월 집계, 비교 가능성, 판단 근거 사본
    ledger.mjs               서버·데모 공용 검증, 중복·버전·참조 검사
    connection.mjs           Apps Script RPC, 확인 응답 검증
    demo.mjs                 분리된 브라우저 원장과 가상 예시
    app.mjs                  영업일·탭·양식·저장 상태와 재시도
    view.mjs                 타임테이블, 집계 카드, 이력 표시
    style.css                다크 그린·세이지·아이보리 및 모바일 탐색
  apps-script/
    Code.gs                  Google 사용자 확인, 초기화, 잠금, 원장 읽기·쓰기
    Engine.gs                공통 ES 모듈에서 빌드한 서버 엔진
    Index.html               스타일·스크립트를 내장한 설치용 화면
    appsscript.json          권한 범위와 한국 시간대
  test/
    domain.test.mjs          계산·날짜·검증·과거 판단 회귀 검사
    sheets-fixture.mjs       Google 서비스의 로컬 모의 구현
    sheets.test.mjs          설치 파일의 원장·인증·잠금·오류 검사
    browser.cjs              PC·모바일, 저장 복구 및 모의 RPC 통합 검사
  qa/
    desktop-today.png        가상값으로 실행한 PC 화면
    mobile-today.png         가상값으로 실행한 모바일 크기 화면
```

`src/`와 로컬 `index.html`이 개발 원본이다. 다음 명령으로 동일한 계산·권한 검증 모듈을 `Engine.gs`와 `Index.html`에 다시 묶는다. 제품 실행·빌드·원장 모의 테스트에는 외부 패키지나 비밀값이 필요하지 않다.

```powershell
node build.mjs
node --test test/domain.test.mjs test/sheets.test.mjs
```

브라우저 검사는 로컬 서버를 켠 상태에서 별도 터미널로 실행한다. 검수한 브라우저 도구는 `playwright-core` 1.64.1과 Chromium이다. 도구가 없는 검수 환경에서는 먼저 다음 두 설치 명령을 사용한다.

```powershell
npm install --no-save --package-lock=false playwright-core@1.64.1
npx playwright-core install chromium
node --test test/browser.cjs
```

`R05_TEST_PORT`는 브라우저 검사가 바라볼 로컬 포트이고 기본값은 `4305`다. `R05_SCREENSHOTS=1`을 설정하면 `qa/`의 데모 화면 캡처 두 장을 갱신한다.

| 브라우저 | Chromium 자동 검사 6개 통과. 데스크톱과 모바일 크기로 계획·성과·마감·판단을 저장하고, 대표 승인과 새로고침 후 이력을 확인했다. 320·390·768·1440px에서 다섯 탭의 가로 넘침과 선택 상태, 키보드 건너뛰기, 메뉴 터치 크기를 검사했다. |
| 설치 파일 | 빌드한 단일 HTML을 로컬 브라우저에서 열었다. 설치용 `Code.gs`와 `Engine.gs`를 모의 Google 서비스로 실행해 두 날짜와 두 역할이 같은 원장을 읽고 쓰는 흐름을 확인했다. 응답 유실 후 한 행만 남았고 오류·마지막 동기화가 화면에 표시됐다. |
| 현장 확인 사항 | 실제 Google 로그인·조직별 계정 식별·시트 권한·할당량·웹 앱 URL, 실물 iOS/Android에서의 키보드와 터치, 3개월간의 관리 시간 절감 효과는 미검증이다. 당근 등 채널은 수기 입력이며 광고·결제·배포 연결은 없다. |

R0.5는 한 사업장용이다. 하루 동일 계획 버전의 실제 집행은 한 번 기록한다. 시간대별 방문이나 여러 광고 각각의 매출 귀속은 추정하지 않는다. 실증 원장은 이력과 판단 근거를 함께 읽으며 한 파일당 이벤트 상한은 10,000건이다. 로컬 데모를 다른 기기와 공유하려면 각 기기에서 별도 가상 일지로 취급한다.
